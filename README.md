# Посуточная аренда квартир — бот и мини-приложение MAX

Площадка Сергея (ИП Тагачин): Самара и Самарская область. Хозяева размещают жильё бесплатно,
модератор (Сергей) проверяет объявления, гости бронируют с подтверждением хозяина.
Бот в MAX: `id637501884609_4_bot` («Посуточная аренда квартир»).

## Как работает
- **Кто может сдавать:** обычный человек только бронирует. Сдавать — после заявки (имя, город, сколько квартир,
  свои или чужие); модераторам она приходит в чат с кнопками «Принять» и «Отказать» (и в разделе «Заявки»).
- **Хозяин:** анкета (черновик сохраняется сам) → фото прямо из приложения (сжимаются на телефоне, без геометок)
  → «Опубликовать».
  Ведёт календарь (закрывает даты), снимает с показа, правит. Новое описание или фото модератор смотрит снова,
  цены и календарь — без проверки.
- **Публикация сразу** (MODERATION=post): объявление попадает в поиск, модератор смотрит после («Всё хорошо» или «Скрыть»).
  Подозрительное (цена ниже 700 ₽ или выше 60 000 ₽, выходные дороже будней втрое, контакты) ждёт проверки до показа.
  MODERATION=pre — сначала проверка, потом поиск.
- **Защита от обмана:** телефоны, ссылки, мессенджеры и «переведите на карту» в описании не сохраняются (shared/trust.ts).
  Жалоба гостя → модератору с кнопками «Скрыть», «Всё в порядке», «Заблокировать хозяина» (объявления снимаются, гостям отмена).
- **Модератор:** объявление приходит в чат с фото и кнопками. То же — во вкладке «Проверка», жалобы сверху.
  Главным становятся командой боту `/admin <код>` (код в `.env.local`, знает только Сергей).
- **Админка** (вкладка у команды): цифры, «Проверка» (жалобы и объявления), «Объявления» (все, снять/вернуть),
  «Люди» (поиск по номеру и имени, блокировка), «Команда» (главный назначает модераторов по номеру), «Журнал» (кто что сделал).
  Модератор не может назначать других, блокировать главного и себя; последнего главного не убрать.
- **Гость:** поиск (город, даты, гости) → карточка → «Забронировать» → номер и согласие → запрос хозяину.
- **Бронь:** запрос держит даты. Хозяин отвечает кнопками в чате или в приложении. Срок ответа 3 часа,
  а если срок выпадает на ночь (22:00–8:00), то до 11 утра. Не ответил — запрос отменяется сам.
  После подтверждения гость получает адрес и телефон хозяина, хозяин — телефон гостя. За день до заезда напоминание обоим.
- **Отзывы:** в день выезда бот просит оценку звёздами прямо в чате; словами — в приложении. Оценить может только тот, кто жил, один раз.
- **Правила отмены:** хозяин выбирает «бесплатно до заезда» или за 1/3/7 дней; поздняя отмена отмечается и видна хозяину.
- **Переписка до брони:** гость пишет хозяину из объявления; хозяину приходит уведомление от бота, ответить можно
  прямо в чате MAX («Ответить» на уведомление) или в приложении. Телефоны и ссылки в сообщениях заменяются на «[скрыто]».
  Список переписок и значок непрочитанных — во вкладке «Моё». Ссылка из бота startapp=chat_<id> открывает переписку.
- **Поиск:** город, даты (только свободное), гости, цена, комнаты, с детьми/животными, удобства; сортировка по цене, оценке, новизне. Избранное.
- **Оплата:** этап 1 — хозяину при заселении. Онлайн-оплата и 5% площадке — этап 2 (нужна ЮKassa на ИП Сергея).

## Демо на Vercel
https://arendbot.vercel.app — ДЕМО, не для настоящих людей: серверы в США (152-ФЗ требует хранить данные россиян в России),
диска нет (данные сбрасываются к тестовым объявлениям при перезапуске), токена бота нет, сообщения в MAX не уходят,
любой открывший — тестовый «главный». Код демо-сервера: server/vercel-demo.ts, сборка: scripts/vercel-build.mjs.
Обновить: `node scripts/vercel-build.mjs && npx vercel deploy --prebuilt --prod` (или пуш в main — Vercel соберёт сам).
GitHub: https://github.com/daaamngg/arendbot

## Запуск
```
npm install
npm run api      # сервер на 8788 (.env.local, см. .env.example)
npm run dev      # мини-приложение на 5197
npm run selftest # проверки сервера
```
`node server/seed-dev.ts` — два тестовых объявления в локальную базу (только разработка).

## Защита от ложных броней
- не больше 3 запросов, ждущих ответа, у одного гостя; бронь не дальше чем на 180 дней;
- хозяин отмечает «Гость не приехал»; это и поздняя отмена — предупреждение; после двух бронировать нельзя;
- завершённые и отменённые брони можно убрать из своего списка (сами брони остаются в базе для споров).

## Перед выкладкой (чек-лист)
- В облачной функции `allowBrowser: false` (вход только из MAX с подписью), `WEBHOOK_SECRET` задан, вебхук подписан.
- Хранилище YDB вместо файла (транзакция брони) и лимиты запросов в базе, а не в памяти функции.
- `MODERATION` по решению Сергея (post — сразу в поиске, pre — сначала проверка).
- Политика конфиденциальности и пользовательское соглашение на ИП Сергея; облако на его аккаунте.
- Тестовые объявления (seed-dev) в облако не попадают — это только локальная база.
- Фото из приложения в облаке складывать в Object Storage (savePhoto в хранилище), не на диск функции.
